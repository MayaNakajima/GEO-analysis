## いちばん簡単な方法：「更新して開く.bat」をダブルクリック

アプリのフォルダにある **`更新して開く.bat`** をダブルクリックするだけで、次の 3 つを自動で行う（Anaconda Prompt 不要）。

1. monitoring の最新 CSV で `analysis.html` を再生成
2. 関係者用の BOX フォルダ（`config.json` の `share_dirs`）へ `analysis.html` をコピー
3. 既定のブラウザで `analysis.html` を開く
   （Windows の「既定のブラウザ」設定＝Chrome／Edge／Firefox 等を使う。`.html` の関連付けがエディタ等でもブラウザで開く。既定ブラウザが取得できない場合は Edge）

> Python は `C:\work\anaconda_install\python.exe` を自動で使う（無ければ `py` → `python` の順に探す）。
> エラー時はウィンドウが閉じずにメッセージが残るので、下の E を参照。
> 関係者は BOX の `GEO-analysis\analysis.html` をダブルクリックで開くだけでよい（最新版は上記でコピー済み）。

以下の A〜B は、コマンドで実行したい場合・設定を変えたい場合の手順。

## A. 初回だけ：config.json の確認

`GEO-analysis\config.json` を開き、パスを自分の環境に合わせる（バックスラッシュは 2 個 `\\` で書く）。

```json
{
  "results_dir": "C:\\Users\\612316\\Documents\\GitHub\\GEO\\monitoring\\data\\results",
  "reports_dir": "C:\\Users\\612316\\Documents\\GitHub\\GEO\\monitoring\\data\\reports",
  "reference_md": "C:\\Users\\612316\\Documents\\GitHub\\GEO\\Set2_実績スクレイピング_reference.md",
  "output_html": "C:\\Users\\612316\\Documents\\GitHub\\GEO-analysis\\analysis.html"
}
```

- `results_dir`：monitoring の CSV 置き場（`results_*.csv` があるフォルダ）。
- `reports_dir`：monitoring のレポート置き場（`index.json`・`insights_*.json` があるフォルダ）。**ホームタブ**の「次にやること」「議論ポイント Q2/Q3」「計測上の注意」の参考値に使う。
  無い・読めない場合も生成は成功し、ホームの該当ブロックが「データなし」になる。一時的に別の場所を使うときは `python generate.py --reports-dir "<フォルダ>"`。
- `measurement_notes`：計測の断絶（例：2026-08-31 回答欠測の修正）。新しい断絶が起きたら `{"date":"YYYY-MM-DD","label":"…","note":"…"}` を追加する。
- `domain_owner`：事業ドメイン → 担当事業（UN / SCH / MED / IS / コーポレート / 横断）。担当が変わったらここを直す（載っていないドメインは「未割当」）。
- `reference_md`：自社実績リファレンスの md ファイル。
- `output_html`：生成する HTML の出力先（既定のままで可）。
- `share_dirs`：生成後に `analysis.html` をコピーする共有フォルダの一覧（BOX 等・省略可）。フォルダが無い場合は警告を出してスキップ。
  コピーしたくないときは `python generate.py --no-share`。

## B. 実行する（Anaconda Prompt）

1. スタートメニューから **「Anaconda Prompt」** を起動する。
2. アプリのフォルダへ移動する（`/d` はドライブが変わっても確実に移動するためのオプション）。

```bat
cd /d C:\Users\612316\Documents\GitHub\GEO-analysis
```

3. スクリプトを実行する（Anaconda では `python` を使う）。

```bat
python generate.py
```

成功すると次のように表示される：

```
[OK] C:\Users\612316\Documents\GitHub\GEO-analysis\analysis.html
     rows=1932  hits=61  files=15
     competitors extracted (miss rows): 5952 mentions
```

`insights:` 行に、ホームで使った示唆レポートのファイル名が出る（「不一致」のときはホームに「示唆は ◯/◯ 実行分に基づく」と出る）。

## C. 見る

生成された `analysis.html` を **ダブルクリックしてブラウザで開く**だけ。
最初に **ホーム**（今回の結論・計測上の注意・次にやること・議論ポイント・各タブへのリンク）が表示される。会議資料にするときは右上の「印刷（A4横）」。
上部タブで以下を切り替える：

0. **ホーム**：関係者向けの入口。ここだけ見れば今回の状況と次の打ち手が分かる。
1. **競合共起 (P1)**：当社が出なかった回答で挙がる競合ランキング。表の行クリックで根拠の回答へ。
2. **多軸クロス集計 (P1)**：行軸・列軸を選んで出現率クロス表。セルクリックで回答全文一覧。Set2 の崖を自動表示。
   軸に「回(run)」を選ぶと全回の出現率が横並びになり、回ごとの推移を1表で確認できる。
3. **過去回比較**：2つの回（A=過去／B=比較）を選び、A→B の出現率デルタ・競合の増減・質問の反転（出た↔消えた）を表示。反転質問クリックで A/B の回答全文を並べて比較。
4. **引用URL (P2)**：ヒット回答の引用URL集計（非グラウンディングの現状は空）。
5. **自社突合 (P2)**：自社サイト掲載実績 × AI 言及有無。「掲載あるが未言及」＝強化余地。
6. **競合サイト (P3)**：将来実装（設計のみ）。

各タブの「この画面の見方」を開くと読み方の説明が出る。上部のフィルタで絞り込み可能。

### フィルタと「回」の見方（定点観測が複数回のとき）

- **全回まとめて**：フィルタを何も選ばない（既定）。全ファイルを合算。
- **回ごと**：フィルタの「回(run)」でファイル1つ（例 `07-27 17:05 r1`）を選ぶ。同じ日に複数回あっても分離できる。
  「タイミング」を選ぶと同一タイミングの r1/r2 をまとめた単位になる。
- **過去回比較**：「過去回比較」タブで A/B と粒度（run/timing）を選ぶ。同一タイミングの r1↔r2 を比べると「ブレ」も確認できる。

## D. 再測定後の更新

**自動更新タスクを登録済みなら、何もしなくてよい**（下記 D-1）。monitoring の計測後、最長1時間ほどで BOX の `analysis.html` が新しくなる。
すぐ見たいときや自動更新を使わない場合は、**`更新して開く.bat` をダブルクリック**（再生成 → BOX へコピー → ブラウザ表示）。
コマンドで行う場合は B を実行（`python generate.py --open` で生成後にブラウザで開く）。

### D-1. 自動更新タスク（タスクスケジューラ）

| 項目 | 内容 |
|---|---|
| タスク名 | `GEO_Analysis_AutoUpdate`（ログオン中のユーザーで実行。BOX Drive がユーザーのセッションでしか使えないため） |
| 実行時刻 | 毎日 14:30 から 1 時間おきに 23:30 まで。PC が止まっていた場合は起動後に実行（monitoring の計測は毎週月曜 13:00＋後追い実行のため、毎日確認する） |
| 内容 | `pythonw generate.py --skip-if-unchanged --log logs\auto_update.log`（ウィンドウは出ない） |
| 変更がないとき | 入力（results CSV・index.json・insights・reference・config・generate.py）が前回の `analysis.html` より新しくなければ **何もしない**（BOX へのコピーもしない。ただし BOX 側が古い・無いときはコピーだけ行う） |
| 計測中のとき | 入力が直近 10 分以内に更新されていたら書き込み途中とみなし、次の回に回す |
| ログ | `GEO-analysis\logs\auto_update.log`（`[OK]`＝再生成、`[SKIP]`＝変更なし、`[ERROR]`＝要対応） |

> **monitoring 側の連携との関係**：monitoring（2026-09-29 以降）は `config/analysis_link.json` の設定により、定期実行の後と GUI で分析ダッシュボードを開くときに
> 本アプリの `generate.py` を実行し Box へ反映する。通常はこちらで最新化され、自動更新タスクは「変更なし」でスキップする**予備**として働く
> （Box へのコピー失敗の再試行、monitoring 側の連携が無効な場合の補完）。どちらも作業フォルダの `generate.py` をそのまま使うため、
> **作業ブランチをチェックアウトしたまま放置しない**（確認前の変更が Box に出てしまう）。作業後は `git checkout main` に戻す。

- **登録／更新**：`register_auto_update.bat` をダブルクリック（開始時刻を変える場合はコマンドで `register_auto_update.bat -Time 15:00`）。
- **解除**：`register_auto_update.bat -Unregister`。
- **動作確認**：タスクスケジューラで `GEO_Analysis_AutoUpdate` を右クリック →「実行する」→ ログに1ブロック追記されること。

## D-2. 毎月：GSC のダウンロード（Google参考値タブ）

Google参考値タブは、GSC（Google Search Console）の管理画面から手動でダウンロードした Excel を読みます。**毎月1回**、次の手順で置いてください。

1. 毎月、第1〜第5営業日に 6 サイトの GSC を開く（CO＝コーポレート／UN＝ユニフォーム／SCH＝スクール／MED＝メディカル／MED-EC＝ECサイト／IS＝インサイトセールス）。
2. 期間を **「前月1日〜前月末日」** にする（**必ず月単位**。月単位でないファイルは「期間集計（参考）」扱いになり、月別の推移に入りません）。
3. 「検索パフォーマンス」と「生成AI機能」をそれぞれ **Excel でエクスポート**（6 サイト × 2 ＝ 12 ファイル）。
4. ファイル名の先頭をサイト略称にして（例 `MED-EC｜GSC｜Performance-on-Search-2026-10-03.xlsx`）、`config.json` の `gsc_dir`
   （現在は `Box\【個人】612316_中島　麻耶\10_data`）に置く。
5. `更新して開く.bat`（または自動更新タスク）で再生成 → 「Google参考値」タブで確認。タブ下部の「GSC ファイルの取り込み状況」で、12 ファイルが「取り込み」になっていることを確認する。

- 同じサイト・同じ月のファイルを置き直したときは、新しい方が使われます（古い方は消さなくてよい）。
- 設問ごとのキーワードは GEO の `monitoring\config\google_keywords.csv`（Excel で編集可・UTF-8 のまま保存）。
- 施策を実施したら `config.json` の `action_notes` に `{"date":"2026-10-15","qids":["Q-C3-A3-B6c-030"],"note":"白衣の選び方ページに比較表を追加"}` の形で記録すると、設問の詳細に表示されます。

- 毎月の **Google 検索チェック**（設問文・観測キーワードを人が Google で検索し、ブックマークレットで記録）は monitoring の GUI で行います
  （手順は GEO の `monitoring\運用手順書_v1.md` の「L. Google 検索チェック」）。記録すると、次の再生成で Google参考値タブに反映されます。

## D-3. 施策の記録（施策管理表・関係者が記入）

Box の `事業推進Div□\DX推進課\生成AI\GEO-analysis\Google参考値_施策管理.xlsx` に、施策の担当者・状態・実施内容を記入します。

1. Excel を開き、該当する **設問ID** の行（全138問が並んでいます）に「担当者」「状態（未着手／対応中／完了／見送り）」「期限」「実施日」「実施内容」「対象ページURL」「メモ」を書いて保存する。
2. 同じ設問で次の施策をしたら、表の下に **行を追加** して同じ設問IDを書く（下の行ほど新しい記録）。
3. 「担当（事業）」を書き換えると、Google参考値タブのその設問の担当が変わる（空なら config.json の domain_owner）。
4. 保存すると、自動更新タスク（毎日14:30〜23:30の1時間おき）か「更新して開く.bat」／定点観測 GUI の「分析ダッシュボードを開く」で、全員が見る analysis.html に反映される。

- 同じファイルを2人が同時に編集すると、Box 上で競合コピー（「…（1）.xlsx」など）ができることがあります。編集は1人ずつ、保存したら閉じてください。
- 設問を追加したときは `python tools\make_action_sheet.py --add-missing` で、新しい設問の行を末尾に足せます（既存の記入は消えません）。
- 表が壊れた・消えたときは、Box のバージョン履歴から戻すか、`python tools\make_action_sheet.py` で作り直します（既にあるときは上書きしません）。

## E. うまく動かないとき

| 症状 | 対処 |
|---|---|
| `results_*.csv が見つかりません` | `config.json` の `results_dir` が正しいか確認。フォルダ内に `results_` で始まる CSV があるか確認。 |
| `python は見つかりません` 等 | Anaconda Prompt から実行しているか確認（通常のコマンドプロンプトでは PATH が通っていない場合あり）。それでもだめなら `py generate.py` を試す。 |
| bat 実行で `[WARN] 共有フォルダが見つかりません` | BOX Drive が起動・同期しているか、`config.json` の `share_dirs` のパスが正しいか確認。ローカルの `analysis.html` は生成済み。 |
| `[WARN] reports_dir が見つかりません` ／ ホームに「データなし」 | `config.json` の `reports_dir` が monitoring の `data\reports` を指しているか確認。CSV 由来の数値（結論・Q1）は表示される。 |
| `[WARN] insights_… を読めません` | そのファイルが壊れている（書き込み途中など）。1つ前の insights が自動で使われ、ホームに実行日の注記が出る。monitoring で再生成すれば解消。 |
| 自動更新で BOX が新しくならない | `logs\auto_update.log` を確認。`[SKIP] 入力に変更がない` が続く → monitoring の計測がまだ（`GEO_AI_Monitoring` のタスク・monitoring の run_log を確認）。`[ERROR]` → メッセージに従い config のパス等を修正。ログが増えていない → `register_auto_update.bat` で再登録。 |
| Google参考値タブが「GSC データなし」 | `config.json` の `gsc_dir` のフォルダに `○○｜GSC｜Performance-on-Search….xlsx` があるか確認。タブ下部の「取り込み状況」に理由が出る（サイト略称を判定できない・期間を読めない等）。 |
| Google参考値の設問キーワードが「未設定」 | `config.json` の `google_keywords_csv` が GEO の `monitoring\config\google_keywords.csv` を指しているか確認。 |
| Google参考値タブの施策が反映されない | 施策管理表を保存したか、Excel で開いたままになっていないか確認。タブ下部「施策の記録の仕方」に最終更新日時と記入行数が出る。状態の書き間違い（未着手／対応中／完了／見送り 以外）は生成ログに [WARN] が出る。 |
| フォルダに移動できない | `cd /d C:\Users\...\GEO-analysis` のように `/d` を付ける。 |
| 文字化けする | CSV は UTF-8 BOM 前提。monitoring が出力したものをそのまま使う。 |
| HTML を開いてもグラフが出ない | 社内ネットで CDN（cdn.jsdelivr.net）がブロックされていないか確認。表・数値はネット無しでも表示される。 |
| 競合候補にノイズ（非企業）が混じる | 仕様上、候補は目視確認前提。除外は `generate.py` の `GENERIC_STOP` に語を追加して再生成。 |
